# Cue

Native tvOS media player (SwiftUI + UIKit), a GPLv3 fork of Orivio TV.
Content comes from Stremio add-ons (AIOStreams, debrid configured inside them).
Syncs with a **Nuvio** account (`Core/NuvioAccount/`, QR at first launch).
Bundle id `app.cue.tv`, URL scheme `cue://`, defaults keys `cue.*`.
Server-facing values (`nuvio_tvos_preferences`, `syncSource: "nuvio"`) must not change.

## How we work

- **Quick iterations; the user verifies on the TV.** For look and feel: make the
  change, one Debug build as the compile check, install on the sim, hand over
  with a short note. No screenshot rounds, no "let me verify" loops.
- Verify yourself only for behaviour or focus bugs, or when asked — not
  while a design is still being iterated (focus is made proper after).
  Tool: `Tools/RemoteDriver/remote.sh "<keys>" [launch args]` presses real
  Siri Remote keys on the sim (`up/down/left/right/select/menu`, `hold`,
  `wait:<s>`, `shot:<name>`, `focus`, `<key>*<n>`; ~20 s per run).
  Launched by the driver (launch args) the player never starts: for
  playback, `simctl launch` and drive without args.
- No test targets or UI test suites unless asked.
- **Unsure what the user means? Ask before building.** Many changes start as a
  discussion; when the user says "lets discuss", propose, don't build.
- Keep old code only when told to; otherwise remove what a change makes unused.
- No placeholders: things that belong together appear together.
- No speed/length multipliers for tuning: change the real values.
- Don't reintroduce anything listed under "Removed / rejected".
- Don't read `docs/*.md` unless the user asks — this file is the summary.
  Exception: before changing a part of the UI, read its section in
  `docs/UI-HISTORY.md`, so nothing already tried gets rebuilt.
  Update this file when a decision changes. Keep it short: what is true now,
  with a reason only where it prevents a mistake.

## Build and run

```bash
xcodebuild -project Cue.xcodeproj -scheme Cue -configuration Debug \
  -destination 'platform=tvOS Simulator,id=2DF61D5F-2062-4C19-A952-EB24AC6EA7C3' \
  -derivedDataPath <scratchpad>/dd build 2>&1 | grep -E "error:|\*\* BUILD" | sort -u
xcrun simctl install 2DF61D5F-2062-4C19-A952-EB24AC6EA7C3 <dd>/Build/Products/Debug-appletvsimulator/Cue.app
xcrun simctl launch --terminate-running-process 2DF61D5F-2062-4C19-A952-EB24AC6EA7C3 app.cue.tv
```

- Debug only while iterating. Release only when the user measures fps.
- The project is generated by **xcodegen** from `project.yml`. Regenerating
  wipes Xcode GUI edits to the scheme: put launch args in `project.yml`
  (`schemes.Cue.run.commandLineArguments`), back up and diff the scheme after,
  tell the user. Prefer adding code to existing files over new files.
- `Cue/Secrets.swift` holds real keys and is gitignored — never commit it.
- Dev launch args: `-detailDemo -detailID tt…` (a show; add `-detailMovie`
  for a film — The Two Towers tt0167261 has a collection), `-detailDemoSeries [tt…]`
  (Breaking Bad default; Re:Zero tt5607616, One Piece tt0388629),
  `-transitionSlowMo` (4×), `-detailsHold`, `-holdMenuDemo`, `-browseDemo <person|genre|keyword|company|network> <tmdb id> <name>`,
  `-folderDemo`, `-moviesDemo`, `-homeFocusCollection`, `-cue.home.billboardAutoPage NO`.
- Settings → Developer holds experiment switches
  (`PerformanceSettingsStore`). Remove options once a decision is made.

## Design rules

- **Direction:** flat artwork, glass controls, one outline for focus. Calm,
  quick motion; a stable 60 fps beats fancy. No accent colours: colour only
  for information (rating sources).
- **Glass only for what floats above the page** (hold menus, source
  picker, dropdowns, toasts): `liquidGlass(in:)`, always as a background, one
  glass everywhere (`AppGlass`). Everything in the page is flat
  (`FlatControl`). Exception: the action buttons' pill at rest (`ActionFace`:
  glass at rest; focused a white capsule, dark content, 5 % larger).
  In the player the glass sits directly on the picture: no shade or dimming under it (a shade made it read dark; without the glass's dark tint it was at times unreadable, so the tint stays).
- **Text:** the system font; 24 pt regular is the base, 23–25 pt the floor.
  Four levels, everywhere (`FixedFocusText`): primary 82 %, body 72 %,
  secondary 62 %, tertiary 50 % (75/65/55/45 was too muted). Never
  brighter. A title and its info line, everywhere (under the box, card
  captions, page headers): the name medium at primary, the line under it
  regular at body; captions out of focus each two levels down (secondary,
  tertiary) (`FixedFocusText.titleFont`/`infoFont`/`titleLevel`/`infoLevel`;
  both regular, the line a level dimmer, read as one; semibold was tried).
- **Motion** (`Motion`): focus 0.3 s, move 0.35 s, present 0.45 s (no-bounce
  springs), fade 0.25 s. One press, one movement. A press on a focused button,
  row or menu entry takes it back to its resting size, level with its
  neighbours, then up again (shrinking below that was tried). Animate transforms and
  opacity only.
- **A press mid-animation** hurries motion, never waits: motion with a known
  end finishes quickly (0.1 s), then the press acts on a settled screen; held,
  never blocked (a press that does nothing reads as missed). Over a load
  (pages, Details) presses are dropped until the page is whole. Long journeys
  (Back's scroll to the top) go at their own pace; a press in their first part
  is dropped.
- **Loading**: one symbol everywhere, three dots rising and falling one after
  the other, the light going with them, a brief rest between rounds
  (`LoadingSymbol`, `LoadingSpinner` in SwiftUI), 64 pt on a page, the text's
  white; in the player too, at once (after 0.5 s, the title's logo or a play symbol
  instead was talked over: left as is). A turning ring, a ripple, dots standing still and a pulsing dot were tried.
- Never alpha 0 on a focusable list (tvOS skips transparent views); hide cell
  contents or mask instead.
- Cards: corners 22 pt continuous (`Spotlight.cornerRadius`), a 2 pt rim
  (`FixedFocusCardEdge`), focus the same edge bright plus a soft shadow, no
  ring, 6 % larger (8, 10 and 12 were tried); Home's fixed box not grown, the posters' height (4 % was tried). One portrait size (`FixedFocusMetrics.posterCard`, 265 × 398).
  A card's progress (Continue Watching, Details' episodes, the Top Shelf):
  the player's bar's look (capsule, 25 % track, 56 % fill cut flat), 6 pt
  (3, scaled, was too faint), 30 pt from the foot and sides; one line above
  it, 22 pt, medium (on the art): "S1:E5" left, the time left or "Up Next" at its end (above and below
  the bar looked odd) (`FixedFocusProgressView`, `Spotlight.state…`).

## How things work

- **Tabs** stay alive once built, built ahead after launch; a switch: the
  old page gone and the new one there in the same frame, no fade, no
  drift (as Netflix) (`switchTab`). (A dissolve over the old felt heavy;
  the new page fading in over the old picture dipped at its end; a plain
  fade didn't feel good; the billboard's paging slide was too much and
  confused with the billboard's; Home drifting in 18–72 pt with its
  picture's edges carried on was liked at 36, then not wanted; Search and
  Settings drifting by a SwiftUI offset stuttered; a parallax and a
  grown picture were tried.)
- **Top bar** (`GlassSidebar`): part of the page, not floating: the tabs as
  words from the page's left edge (28 pt medium; the current one primary,
  the others secondary), the avatar at the right edge, nothing behind them;
  focused, the season buttons' focus (`ActionFace`: the white capsule
  growing in on the item, 5 % larger, dark text; quicker than the
  buttons': 0.12 s in, 0.28 s out, the fade linear (0.35 slow, 0.2 abrupt here; easing out was tried), 6 pt
  apart; a plain fade with no growth was tried; nothing travels: a capsule
  gliding along the bar was slow and odd to the avatar). Focus moving along it
  switches tab. Pages are laid out below it. On Home, Movies and Series it
  sits on the billboard and goes up with it into the rows (same distance,
  same move: `TopBarPlace`, `lifted`); off a tab's root, into Details or a
  trailer it moves out the top (`hidden`), always in the view tree,
  disabled while hidden. (The floating glass pill, and auto-hiding it,
  were dropped, the setting with them.)
- **Home rows are UIKit**: native focus, scrolling off, rows moved with Core
  Animation in `didUpdateFocus`. A fixed box at the focus spot for most rows;
  collections, Continue Watching and Saved for Later have moving focus.
  SwiftUI scrolling was rejected (main-thread animation, lost targets).
  What a row shows is what Select acts on: the row focus is in keeps its
  titles, order and pictures until focus leaves it (a reordered Continue
  Watching showed one title and played another); other rows update at once,
  new pictures in place (`heldRows`, `refreshArt`).
  Continue Watching's art is the episode's TMDB still as Details', else the
  add-on's, looked up under the launch curtain (`ContinueStills`).
- **Catalogs** are pulled: fresh at every launch (under the curtain), then
  again once an hour old — on coming back, a tab switch, and while Home sits
  open (checked every 5 min). A refresh's billboard picks swap in only while
  no billboard is on screen (`BillboardSight`).
- **Under Home's box** (the posters' height, not grown): no name, the
  facts line in the title's style, then the description, up to 4 lines,
  top-aligned, secondary (badges there, on the line or in the box, were
  tried: removed). Captions under cards 24 pt. Row names 34 pt semibold,
  a little low in their line, near their cards.
- **Billboard** (Details shares it): the description between the tagline
  and the buttons, 600 pt wide, 3 lines, in Apple TV's vibrancy with a 30 %
  white over it (`VibrantSummary`; plain at body level was hard to read).
- **Billboard**: picture in UIKit (`StagePictureView`), text in SwiftUI,
  content from `BillboardPicks`, buttons in their own host
  (`BillboardControls`), dots in UIKit on Left/Right's spring, the timer's
  fill a linear UIView animation (`BillboardDotsView`: in SwiftUI the main
  thread's paging work made them stutter and flicker); moved up
  with the billboard by the rows (`billboardOverlayShift`). No Play button:
  Details is the way to play.
- **Details** shares the billboard's text and shade. Into Details is
  `DetailTransition`, all Core Animation; from the billboard in place
  (`openInPlace`). From Home, Movies and Series it's a layer over the page
  (`detailLayers`), so Home stays laid out; elsewhere it's pushed. Other pages
  use `PageFade`. `trail`: Back is never more than two pages deep.
- **Back**: on a tab's page, focus to the top bar in one press; below the
  billboard or first row the page goes back up to it on the way, focus
  never on its buttons (`passUp`; landing on Details first was not wanted)
  (Details: out). The app is never left by Back (`BackCatch`).
- **Loading**: nothing pops in. Pages wait under their background until data
  and first-screen pictures are ready (`PagePreparer`, `PageLoad`, 4 s cap,
  then placeholders in the final layout: `FixedFocusPlaceholder`). Launch runs
  under a curtain (`LaunchPreloader`): "Who's watching?" (`ProfileGate`)
  from the first frame tvOS gives us, always, one profile too (a choice:
  Add Profile is there); no play. No press for 5 s: the focused profile is
  picked (not a locked one), "Continuing as …" under the names for the last
  2 s; any press stops it for good (`autoPick`). Picked before Home is
  ready: the rest fades, the avatar waits in the middle (no breathing) over
  the stage's status line (`SweepLine`): one line, a hint, not the steps
  (those only in the probe), one of three per launch, never changing
  mid-wait: "Assembling the lineup", "Gathering the cast", "Aligning the
  satellites" (`LaunchPreloader.lines`; two lines, then plain wording, were
  tried). Ready at the pick: it flies at once. The curtain lifts once the minimum is in and 3 s have passed
  (`minimum`, the floor), whichever is later, however long the minimum
  takes; 15 s is only a safety ceiling for a broken network (`ceiling`, then
  placeholders). Back from the background instant (no curtain; the gate at
  once after 4 h). The minimum, in order: saved rows; every catalog fresh
  (each at most 8 s, `catalogWait`, then its saved copy) and the Nuvio pull
  (`sync`); the picks from those; what the first screen draws and one press
  reaches (`minimumJobs`: the billboard's first three, the first row's
  cards, the box's first card in the 3 rows below, Continue Watching's
  stills). Then the rest of Home, nearest first (`deep`: Details' data,
  every row's records, their pictures on disk at their sizes, not decoded:
  at 4K that would evict the first screen's), on the curtain until the
  floor, then on behind Home. One queue for all loading ahead
  (`LoadQueue`, after `LaunchPreloader`): bands focus, launch, deep; lanes
  data and pictures, 3 each, deep leaving room for focus; each kind's count
  and time to the probe when it runs dry. Warm, the whole of Home was done
  5.7 s after launch.
- **Pictures**: posters and the box from add-ons (honoured: we're a Nuvio
  client); billboard and Details from TMDB's backdrop. Decoded at a few
  named sizes (`PictureSize`: poster, landscape, card logo, screen, logo),
  each its largest on screen at the screen's scale, nothing more (1.5× and
  a ladder of sizes cost up to 3× the memory). On disk the original plus
  a copy at each size decoded smaller (`keepResized`), read first, so a
  disk read doesn't decode a 4K original again. Three decodes at a time,
  never on the main thread (`DecodeGate`): what's on screen first, with a
  slot of its own; ahead at most two, newest first, dropped once focus has
  moved on (a held Left/Right ran dozens at once: under 30 fps, the box
  waiting behind passed titles). Decoded ahead through the queue's focus
  band (`LoadQueue`, `PicturePreloader`): Home's reachable titles at once
  (`preloadReachable`: Left/Right's next, and Up/Down's one title per row in
  the 3 nearest rows each way — every row would evict the cache at 4K), and
  Details' one picture as focus settles (`TitlePreloader`). A grown card's
  picture still late: the poster stays until it's in. The same titles'
  records are brought up to date ahead too, after a 0.3 s rest (MDBList
  counts requests), chips drawn ahead (`TitleExtras`).
- **Title records** (`TitleRecords`, end of `RequestCache.swift`): per title
  what its text draws beyond the catalog — a series' size and episode dates
  (AIRING is read from them when drawn), TMDB's status and tagline,
  MDBList's ratings — all in one file read into memory at launch, so a title
  seen before draws badge, ratings and season count with its text (separate
  async caches per kind came late). Shown as stored, asked again once a day,
  redrawn only if the answer differs. Launch refreshes what's reachable first
  under the curtain, then every Home row's (first 15 each) in the queue's
  deep band, again on coming back if an hour has passed. Not pictures, not the
  facts line or logo (in time already).
- **Progress**: under 30 s played in a session, nothing is saved (a Start Over
  keeps its old position). After that the real position, seeks included: to
  the device every 10 s, to Nuvio on the first save and every 30 s; both on
  pause, leaving the app and exit. Finished at 95 %. Started means past 30 s
  (`WatchProgress.isStarted`); "Up Next" only ever means unstarted.
  Next Up cards (made from watched history) only for shows with an episode
  watched in the last 30 days (`nextUpWindow`): removing one is kept on the
  device only, Nuvio has no field for it (NuvioTV keeps it local too).
- **Nuvio sync** follows NuvioTV's schedule: a full pull at launch (the
  curtain waits on it), on coming back and on a tab switch (2.5 s settle, at
  most every 2 min, `openSyncFloor`), and every 15 min (`autoSyncInterval`;
  the light pass while playing). Pushes go on every change. No 30 s timers.
- **Trailers** (`StageTrailer`, `TrailerPlayer.swift`): 2 s rest on the
  buttons, one `AVPlayer` handed between Home, Details and full screen, YouTube
  HLS rewritten to H.264 720p+ (`TrailerPlaylist`). Full screen
  (`TrailerController`) has the player's bar and presses (`PlayerTransport`,
  `PlayerOverlay`, shared with `PlayerController`): the title's name, no
  buttons, shelf or stills; with the controls up, Up hides them and Down
  closes ("Back to Details" with a chevron where the shelf's tabs peek).
  It has no picture of its own: a clear cover, at once, over Details'
  picture where the trailer plays; Details' text, buttons and shade fade
  out under it and back as it goes (0.45 s), the sound rising from silence
  (0.8 s) and falling away on the way out if Details' is off. Be gentle on YouTube:
  resolve ahead for 3 titles only, hold off 30 min on a bot check. Trailers
  keep their own `AVPlayer`.
- **Sources**: no sorting or filtering of the links themselves, the add-ons' order; only what can play is a link (a donation entry or other `externalUrl` isn't) (the source list's add-on pills and refresh stay: they choose whose links show); Play, Resume and Start Over

  (`SourcePanel`).

  `swift Tools/AppIcon/render.swift`.

**Lessons:** a UIView animation nested in the moves' spring takes the spring's
timing, so its own timing needs Core Animation; a bare sublayer resizes on Core
Animation's own 0.25 s, so make it a view (`FixedFocusShade`); two identical
layers crossfading dip (flicker); a SwiftUI hosting view's own opacity darkens
the screen mid-fade, so fade a plain view holding it; never draw text twice;
`CATransaction.flush()` or CA starts a runloop late; a view going out is frozen,
environment changes only reach it through its transition; a wholly covered page
isn't drawn until revealed, so covers are 99.5 % opaque.

## Removed / rejected (don't bring back)

- Removed features: cloud library, Plex/Jellyfin, Live TV/M3U, JS plugins,
  in-app debrid/TorrServer, themes/accent palettes, external players,
  Trakt/SIMKL accounts (public Trakt lists stay), Stremio account, the
  Dynamic background (title colours following focus), Nuvio's
  stream badges (Badger/Fusion: not liked; their blob feature is left alone).
- Removed from the screen: the launch's numbers (the steps still go to the
  probe log, `LaunchPreloader.line`).
- Ask before touching the Nuvio sync.
- Rejected mechanisms: tvOS's own sidebar, the system's context menus, SwiftUI
