# Cue

Native tvOS media player (SwiftUI + UIKit), a GPLv3 fork of Orivio TV.
Content comes from Stremio add-ons (AIOStreams, debrid configured inside them).
Syncs with a **Nuvio** account (`Core/NuvioAccount/`, QR at first launch).
Bundle id `app.cue.tv`, URL scheme `cue://`, defaults keys `cue.*`.
Server-facing values (`nuvio_tvos_preferences`, `syncSource: "nuvio"`) must not change.

## How we work

- **Quick iterations; the user verifies on the TV.** For look and feel: make the
  change, one Debug build as the compile check, install on the sim, hand over
  with a short note. No screenshot rounds, no "let me verify" loops.
- Verify yourself only for behaviour or focus bugs, or when asked — not
  while a design is still being iterated (focus is made proper after).
  Tool: `Tools/RemoteDriver/remote.sh "<keys>" [launch args]` presses real
  Siri Remote keys on the sim (`up/down/left/right/select/menu`, `hold`,
  `wait:<s>`, `shot:<name>`, `focus`, `<key>*<n>`; ~20 s per run).
- No test targets or UI test suites unless asked.
- **Unsure what the user means? Ask before building.** Many changes start as a
  discussion; when the user says "lets discuss", propose, don't build.
- Keep old code only when told to; otherwise remove what a change makes unused.
- No placeholders: things that belong together appear together.
- No speed/length multipliers for tuning: change the real values.
- Don't reintroduce anything listed under "Removed / rejected".
- Don't read `docs/*.md` unless the user asks — this file is the summary.
  Exception: before changing a part of the UI, read its section in
  `docs/UI-HISTORY.md`, so nothing already tried gets rebuilt.
  Update this file when a decision changes. Keep it short: what is true now,
  with a reason only where it prevents a mistake.

## Build and run

```bash
xcodebuild -project Cue.xcodeproj -scheme Cue -configuration Debug \
  -destination 'platform=tvOS Simulator,id=2DF61D5F-2062-4C19-A952-EB24AC6EA7C3' \
  -derivedDataPath <scratchpad>/dd build 2>&1 | grep -E "error:|\*\* BUILD" | sort -u
xcrun simctl install 2DF61D5F-2062-4C19-A952-EB24AC6EA7C3 <dd>/Build/Products/Debug-appletvsimulator/Cue.app
xcrun simctl launch --terminate-running-process 2DF61D5F-2062-4C19-A952-EB24AC6EA7C3 app.cue.tv
```

- Debug only while iterating. Release only when the user measures fps.
- The project is generated by **xcodegen** from `project.yml`. Regenerating
  wipes Xcode GUI edits to the scheme: put launch args in `project.yml`
  (`schemes.Cue.run.commandLineArguments`), back up and diff the scheme after,
  tell the user. Prefer adding code to existing files over new files.
- `Cue/Secrets.swift` holds real keys and is gitignored — never commit it.
- Dev launch args: `-detailDemo -detailID tt…` (a show; add `-detailMovie`
  for a film — The Two Towers tt0167261 has a collection), `-detailDemoSeries [tt…]`
  (Breaking Bad default; Re:Zero tt5607616, One Piece tt0388629),
  `-transitionSlowMo` (4×), `-detailsHold`, `-holdMenuDemo`, `-browseDemo <person|genre|keyword|company|network> <tmdb id> <name>`,
  `-folderDemo`, `-moviesDemo`, `-homeFocusCollection`, `-cue.home.billboardAutoPage NO`.
- Settings → Developer holds experiment switches
  (`PerformanceSettingsStore`). Remove options once a decision is made.

## Design rules

- **Direction:** flat artwork, glass controls, one outline for focus. Calm,
  quick motion; a stable 60 fps beats fancy. No accent colours: colour only
  for information (rating sources).
- **Glass only for what floats above the page** (top bar, hold menus, source
  picker, dropdowns, toasts): `liquidGlass(in:)`, always as a background, one
  glass everywhere (`AppGlass`). Everything in the page is flat
  (`FlatControl`). Exception: the action buttons' pill at rest (`ActionFace`:
  glass at rest; focused a white capsule, dark content, 5 % larger).
- **Text:** the system font; 24 pt regular is the base, 23–25 pt the floor.
  Four levels, everywhere (`FixedFocusText`): primary 75 %, body 65 %,
  secondary 55 %, tertiary 45 %. Never brighter.
- **Motion** (`Motion`): focus 0.3 s, move 0.35 s, present 0.45 s (no-bounce
  springs), fade 0.25 s. One press, one movement. Animate transforms and
  opacity only.
- **A press mid-animation** hurries motion, never waits: motion with a known
  end finishes quickly (0.1 s), then the press acts on a settled screen; held,
  never blocked (a press that does nothing reads as missed). Over a load
  (pages, Details) presses are dropped until the page is whole. Long journeys
  (Back's scroll to the top) go at their own pace; a press in their first part
  is dropped.
- Never alpha 0 on a focusable list (tvOS skips transparent views); hide cell
  contents or mask instead.
- Cards: corners 22 pt continuous (`Spotlight.cornerRadius`), a 2 pt rim
  (`FixedFocusCardEdge`), focus the same edge bright plus a soft shadow, no
  ring. One portrait size (`FixedFocusMetrics.posterCard`, 265 × 398).

## How things work

- **Tabs** stay alive once built, built ahead after launch; a switch is a
  0.25 s dissolve, the new page whole under the old (`switchTab`).
- **Top bar** hides by moving out the top, always in the view tree, disabled
  while hidden (`GlassSidebar.hidden`).
- **Home rows are UIKit**: native focus, scrolling off, rows moved with Core
  Animation in `didUpdateFocus`. A fixed box at the focus spot for most rows;
  collections, Continue Watching and Saved for Later have moving focus.
  SwiftUI scrolling was rejected (main-thread animation, lost targets).
- **Billboard**: picture in UIKit (`StagePictureView`), text in SwiftUI,
  content from `BillboardPicks`, buttons in their own host
  (`BillboardControls`). No Play button: Details is the way to play.
- **Details** shares the billboard's text and shade. Into Details is
  `DetailTransition`, all Core Animation; from the billboard in place
  (`openInPlace`). From Home, Movies and Series it's a layer over the page
  (`detailLayers`), so Home stays laid out; elsewhere it's pushed. Other pages
  use `PageFade`. `trail`: Back is never more than two pages deep.
- **Back**: below the billboard or first row, up to it first; there, the top
  bar (Details: out). The app is never left by Back (`BackCatch`).
- **Loading**: nothing pops in. Pages wait under their background until data
  and first-screen pictures are ready (`PagePreparer`, `PageLoad`, 4 s cap,
  then placeholders in the final layout: `FixedFocusPlaceholder`). Launch runs
  under a curtain (`LaunchPreloader`, `ProfileGate` for "Who's watching?").
- **Pictures**: posters and the box from add-ons; billboard and Details from
  TMDB's backdrop, decoded as focus settles (`TitlePreloader`).
- **Progress**: under 30 s played in a session, nothing is saved (a Start Over
  keeps its old position). After that the real position, seeks included: to
  the device every 10 s, to Nuvio on the first save and every 30 s; both on
  pause, leaving the app and exit. Finished at 95 %. Started means past 30 s
  (`WatchProgress.isStarted`); "Up Next" only ever means unstarted.
- **Trailers** (`StageTrailer`, `TrailerPlayer.swift`): 2 s rest on the
  buttons, one `AVPlayer` handed between Home, Details and full screen, YouTube
  HLS rewritten to H.264 720p+ (`TrailerPlaylist`). Be gentle on YouTube:
  resolve ahead for 3 titles only, hold off 30 min on a bot check. Trailers
  keep their own `AVPlayer` through the player rework.
- **Sources**: no sorting or filtering, the add-ons' order; Play, Resume and Start Over
  take the first link (`PlayLauncher`); a link that fails or shows
  no frame in 20 s: the next, silently, up to 3 times, then the source list; 5-min cache; none remembered. Hold Play: the source list
  (`SourcePanel`).
- **Search**: `.searchable` with TMDB behind it, not the add-ons' catalogs;
  Cue's own order (`SearchViewModel.ranked`); titles play by their IMDb ids.
  Only completions in the suggestions: a Button froze Search.
- **Hold menus** are Cue's own `HoldMenu`: the system's ate the next press.
- **Settings** (`ATVSettingsView`, `SettingsKit`): Apple TV's Settings measured
  and recreated, one level at a time; focus by name (`settingsRowFocus`).
  What's only to read takes no focus. Playback and Developer are still on the
  old cards. Profile management lives under Nuvio.
- **Background**: one still picture, Bands (`BandsPicture`); Dynamic follows
  the focused title (`TitleBackground`).
- **App icon and Top Shelf** are generated, never hand-edited:
  `swift Tools/AppIcon/render.swift`.

**Lessons:** a UIView animation nested in the moves' spring takes the spring's
timing, so its own timing needs Core Animation; a bare sublayer resizes on Core
Animation's own 0.25 s, so make it a view (`FixedFocusShade`); two identical
layers crossfading dip (flicker); a SwiftUI hosting view's own opacity darkens
the screen mid-fade, so fade a plain view holding it; never draw text twice;
`CATransaction.flush()` or CA starts a runloop late; a view going out is frozen,
environment changes only reach it through its transition; a wholly covered page
isn't drawn until revealed, so covers are 99.5 % opaque.

## Removed / rejected (don't bring back)

- Removed features: cloud library, Plex/Jellyfin, Live TV/M3U, JS plugins,
  in-app debrid/TorrServer, themes/accent palettes, external players,
  Trakt/SIMKL accounts (public Trakt lists stay), Stremio account.
- Removed from the screen: the launch's numbers (the steps still go to the
  probe log, `LaunchPreloader.line`).
- Ask before touching the Nuvio sync.
- Rejected mechanisms: tvOS's own sidebar, the system's context menus, SwiftUI
  scrolling for the rows, the add-ons' catalogs for Search, sorting or
  filtering sources, a remembered source.
- Rejected looks: glows, underlines, dimming the screen for the top bar, bouncy springs, "through colour" / cascade /
  wipe transitions, billboard strip above the rows; on the billboard's
  Left/Right: a full page scroll (too much movement), the text's parts
  staggered (cascade).
